# FA-DCG V1.0 / V1.1 Design Q&A

Date: 2026-05-20

## Context

This log records the discussion around why the original `LightFADC`
implementation is now treated as FA-DCG V1.0, why the accepted optimized
implementation is treated as FA-DCG V1.1, and what lessons should guide later
FA-DCG work.

## Q1: What are the main problems in LightFADC / FA-DCG V1.0?

FA-DCG V1.0 has several implementation and modeling problems:

1. It performs per-channel Python-loop convolution inside `forward`.
   This is very slow for 512, 1024, and especially 4096 channels.

2. Its dilation parameter is not effectively learnable. The code converts
   dilation values into Python integers, which cuts off gradient flow through
   dilation selection.

3. The FCN wrapper creates `up_dim` dynamically inside `forward`. This is unsafe
   for optimizer construction, checkpointing, model export, and reproducibility.

4. The FCN version applies FA-DCG-like processing at a 4096-channel stage. This
   produces severe latency overhead while not being a natural feature-extraction
   location.

5. The implementation behavior is not fully aligned with the paper narrative.
   In practice, V1.0 behaves more like a fixed-dilation depthwise residual
   enhancement block with channel gating, not a truly learnable dilation
   adaptation module.

6. The insertion position is questionable. If FA-DCG is intended to operate at
   the feature-extraction level, it should be placed earlier or in mid-early
   feature stages, not mainly in middle/late classification stages.

## Q2: If FA-DCG V1.0 has so many problems, why did it still improve results?

The likely reason is that the effective part of V1.0 is still useful, even if
the intended learnable dilation mechanism is flawed.

The actual useful computation is close to:

```text
Y = X + alpha * gate(depthwise_conv(X)) * depthwise_conv(X)
```

This gives the model three useful behaviors:

1. **Depthwise residual spatial enhancement**

   Each channel receives an independent spatial filtering operation. For SAR
   flood segmentation, this can still improve local texture, boundary, and
   region-consistency features.

2. **Channel-wise response selection**

   The GAP + 1x1 MLP + sigmoid gate behaves like a channel attention mechanism.
   It can suppress unreliable responses and amplify channels related to water,
   boundary, shadow suppression, or low-backscatter regions.

3. **Stable residual fusion**

   The residual path and learnable `alpha` make the module conservative. Even if
   the enhancement branch is imperfect, the original backbone feature is still
   preserved.

Thus, V1.0 likely improved metrics mainly because of:

```text
depthwise spatial filtering
+ channel recalibration
+ residual controlled enhancement
```

not because of a truly trainable dilation preference.

## Q3: What likely contributed most to the observed improvement?

The estimated contribution order is:

1. Channel gate / channel attention effect.
2. Depthwise spatial feature enhancement.
3. Residual `alpha` fusion, which stabilizes training.
4. Added nonlinear capacity and regularization.
5. Learnable dilation, which likely contributed little in V1.0 because the
   implementation prevents meaningful gradient-based dilation learning.

## Q4: Why is FA-DCG V1.1 accepted as the new baseline?

FA-DCG V1.1 keeps the effective V1.0 computation path but fixes the engineering
defects:

1. It replaces the per-channel Python loop with vectorized grouped depthwise
   convolution.

2. It preserves the original effective behavior instead of adopting the failed
   task_002b structural rewrite.

3. It keeps the original FCN and U-Net insertion paths for comparability.

4. It moves FCN `up_dim` registration into `__init__`.

5. It maintains the same parameter count as V1.0.

6. Seed 2024 validation results showed no significant metric drop:

| Model | V1.0 mIoU | V1.1 mIoU | Delta mIoU | V1.0 Dice | V1.1 Dice | Delta Dice |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| FCN + FA-DCG | 0.844849 | 0.842804 | -0.002045 | 0.907507 | 0.905853 | -0.001654 |
| U-Net + FA-DCG | 0.896663 | 0.892461 | -0.004202 | 0.941023 | 0.938098 | -0.002925 |

7. Speed improved substantially in the benchmark:

| Model | V1.0 latency | V1.1 latency |
| --- | ---: | ---: |
| FCN + FA-DCG | 214.826 ms | 8.317 ms |
| U-Net + FA-DCG | 65.931 ms | 20.350 ms |

## Q5: What should guide future FA-DCG versions?

Future FA-DCG work should not blindly inherit V1.0's insertion position or
overstate V1.0's dilation-learning behavior.

The next version should focus on:

```text
early/mid feature-level enhancement
+ multi-scale or frequency-conditioned depthwise filtering
+ channel or frequency-aware gating
+ residual controlled fusion
```

Candidate insertion points should move closer to feature extraction, such as
early or mid-early encoder stages, rather than relying mainly on middle/late
classification layers.

FA-DCG V1.0 should remain a historical reference. FA-DCG V1.1 should be the
engineering baseline for subsequent experiments.
